# figma-lean — исправленная сборка 2026-10-08

Включён как дополнительный модуль навыка Alfa Bank. Происхождение, локальные
изменения инструкций и отсутствие лицензии в исходном архиве указаны в
[THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md). Основная инструкция
Alfa определяет дизайн-систему и процесс согласования, этот модуль — операции Figma.

Библиотека операций с Figma, локальная карта файла и реестр дизайн-системы для Claude Code и Codex. Сторонних npm-зависимостей нет; нужен Node.js 18+ и официальный Figma-плагин с `use_figma`.

Агент пишет короткий вызов `fx`, а библиотека подставляется программно. Полные результаты сканов сохраняются на диске, агент получает компактную сводку. Это сокращает повторную генерацию кода и чтение файла; измеренная экономия денег или токенов не заявляется.

## Claude Code

1. Скопировать папку `figma-lean` в `~/.claude/skills/`.
2. Скопировать `recipes/*.js` в `~/.claude/figma-lean/recipes/`, сохранив собственные версии перед заменой.
3. В новой сессии вызвать `/figma-lean`, затем проверить:

```bash
node ~/.claude/skills/figma-lean/tools/fx.mjs doctor
```

Хуки объявлены в `figma-lean/SKILL.md`; по умолчанию рассчитаны на этот путь установки. Они не дают автоматического разрешения на изменения. Другую папку данных задаёт `FIGMA_LEAN_HOME`.

## Codex

Из распакованного архива:

```bash
node install-codex.mjs
```

Установщик копирует навык в `${CODEX_HOME:-~/.codex}/skills/figma-lean`, рецепты и рабочие данные — в `${XDG_DATA_HOME:-~/.local/share}/figma-lean` (или `FIGMA_LEAN_HOME`). Существующие файлы навыка и рецептов сохраняются в резервные копии. Claude-хуки, разрешения, плагины и `config.toml` не меняются. Для обнаружения нового навыка может понадобиться новый чат.

В Codex используется отдельная инструкция `codex/SKILL.md` и `tools/codex-bridge.js`: сборка скрипта → официальный Figma-инструмент → сохранение и сжатие ответа. Библиотека и исходный большой ответ не печатаются в контекст. Изображения передаются отдельно без вывода base64. Ошибка обработки ответа не повторяет удалённую правку.

## Что исправлено

- Создание экземпляра и набора вариантов проверяет разрешённого родителя до изменений.
- Привязка токена сохраняет остальные заливки и обводки; для нескольких SOLID-заливок нужен явный индекс.
- Финальный QA проверяет затронутые контейнеры и показывает ограничения. Все созданные/изменённые ID возвращаются структурированно и сохраняются полностью на диске; в кратком отчёте остаются счётчики и путь.
- Крупные элементы и длинные тексты передаются фрагментами без потерь, включая Unicode.
- Повторный скан заменяет карту после получения всех частей; неполный или конфликтующий скан не удаляет старую карту.
- Имена из вложенных рецептов учитываются при поиске токенов и стилей.
- Обрабатываются вложенные MCP-ответы и доверенные локальные ссылки на полный результат поиска. Недоступный исходный ответ не выдумывается.
- Импорт компонента пробует резервные ключи и доступный главный компонент экземпляра; нерабочие ключи понижаются для соответствующего файла после успешного fallback.
- Клоны восстанавливают поддерживаемые ссылки свойств; неподдерживаемое восстановление выдаёт предупреждение.
- `cprops` повторно связывает все подходящие слои и проверяет типы до изменений.
- `texts` сохраняет полный текст, смешанные диапазоны, имена стилей и все заливки/токены; сокращённые предпросмотры явно помечаются.

## Проверки и границы

Из корня архива:

```bash
node --test figma-lean/tests/*.test.mjs
```

В этой сборке на macOS / Node.js 22.22.3 прошли 36/36 тестов и 15/15 встроенных проверок doctor. Установленный навык валиден и обнаружен новым процессом Codex как enabled. Мост также проверен внутри functions.exec с имитированным ответом Figma. Тесты используют временные данные и имитацию Figma API. `doctor` дополнительно проверяет локальную сборку и обработчики. Они не подтверждают авторизацию Figma, поведение её сервера, Windows/Linux или визуальную приёмку макета. Реальный Figma-файл при исправлении сборки не изменялся.

Scope ограничивает помощники, но не произвольный Plugin API-код. Карта — кэш; при внешних изменениях требуется повторный скан. Структурная проверка не заменяет просмотр композиции, переносов текста, цвета и читаемости.

Инструкция Alfa core-ds в `references/core-ds.md` применяется только к проектам с этой системой. Остальные проекты используют собственные библиотеки и правила.
